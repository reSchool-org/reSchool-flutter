# reSchool

reSchool - неофициальный клиент для электронного дневника [eSchool](https://eschool.center), написанный на Flutter. В нём можно смотреть расписание, оценки, домашние задания, чаты. Исходный код открыт.

## Возможности

### Дневник и оценки

Расписание показывает уроки на неделю, выделяет текущий урок и отсчитывает время до конца урока или перемены. В карточке урока есть тема, домашнее задание, оценки, кабинет и учитель.

Оценки можно посмотреть по каждому предмету за четверть, полугодие или год. Средний балл рассчитывается автоматически и выделяется цветом.

### Домашние задания

Задания собраны в отдельный список со сроками сдачи. Прикреплённые файлы можно скачать и открыть. В тексте заданий поддерживаются форматирование, таблицы, ссылки, математические формулы и изображения, которые можно увеличить.

### Переписка

В приложении есть личные и групповые чаты, в том числе беседы класса. Можно отправлять фотографии и документы, загружать старые сообщения и искать по истории. Найденное сообщение открывается в контексте беседы.

Свои сообщения можно редактировать и удалять, если это разрешено сервером и не истёк отведённый срок. Вложения беседы доступны отдельно, с поиском по имени файла.

Справочник сотрудников показывает подразделения и должности. В нём можно найти человека и перейти в личный чат. Справочник также доступен в разделе «Ещё».

### Настройки

Светлая и тёмная темы переключаются вручную или автоматически. В профиле отображаются данные пользователя и аватар.

Расписание звонков можно задать вручную или выбрать готовый вариант для ФМЛ №30 или ФМЛ №239. Если школьные часы спешат или отстают, можно настроить общее смещение времени.

## Иконки приложения

Иконки всех платформ генерируются из `assets/logo.svg` командой `python3 scripts/generate_icons.py`. Нужны `rsvg-convert` (librsvg), ImageMagick и Dart с установленными зависимостями проекта (`flutter pub get`).

Скрипт создаёт скруглённые PNG для favicon, обычных веб-иконок, Android и Windows, а также иконки macOS с отступом. Для адаптивных Android-иконок, maskable-иконок веб-приложения и iOS форму задаёт система; для них подготовлены отдельные ресурсы с подходящими отступами.

## Хранение данных

Логин, пароль и сессионные куки хранятся с помощью `flutter_secure_storage`, который использует системные средства защиты: Android Keystore и iOS Keychain.

Основные школьные данные приложение получает из API `eschool.center`. Если включить облачные функции, учётные данные будут передаваться выбранному серверу для фоновых проверок, а уведомления - отправляться напрямую в настроенный Telegram. Подключайте только те серверы, которым доверяете.

## Технологии

Приложение написано на Dart и Flutter, код организован по MVVM. Основные зависимости:

- `provider` - управление состоянием;
- `http` - сетевые запросы;
- `flutter_secure_storage` и `crypto` - хранение учётных данных и криптография;
- `path_provider`, `open_filex`, `file_picker`, `image_picker` - работа с файлами и изображениями;
- `shared_preferences`, `intl`, `url_launcher` - настройки, форматирование и открытие ссылок.

## Запуск из исходников

### Требования

- Flutter SDK 3.47.4 - эта версия закреплена в автоматических сборках; минимальная версия - 3.47.0.
- Dart SDK.
- Android Studio или Xcode для сборки под соответствующую мобильную платформу.
- JDK 17, как в автоматических сборках, или JDK 21 для сборки Android с Gradle 9.1.0.

Проверьте Java, которую использует Flutter, командой `flutter doctor -v`. Flutter может выбирать JDK из Android Studio вместо системной Java. Чтобы использовать установленную JDK 21, укажите её явно:

```bash
# пример для Arch Linux с установленной JDK 21
flutter config --jdk-dir=/usr/lib/jvm/java-21-openjdk
```

Эта настройка действует для всех Flutter-проектов на компьютере.

### Сборка и запуск

Клонируйте репозиторий, установите зависимости и запустите приложение:

```bash
git clone https://github.com/reSchool-org/reSchool-flutter.git
cd reSchool-flutter
flutter pub get
flutter run
```

## Android-релизы и обновления

GitHub Actions `Build Android, Windows & Linux` при выборе Android собирает AAB
и четыре подписанных APK. Артефакт `android-apk` содержит готовые имена для релиза
`v<версия>` (версия берётся из `pubspec.yaml` без номера после `+`):

- `reSchool-v<версия>.apk` — общий APK для первой установки и старых клиентов;
- `reSchool-v<версия>-arm64-v8a.apk`;
- `reSchool-v<версия>-armeabi-v7a.apk`;
- `reSchool-v<версия>-x86_64.apk`.

Workflow создаёт артефакты без публикации. При публикации GitHub Release загрузите
все четыре APK с этими именами. Общий APK нельзя переименовывать: старые версии
приложения скачивают именно его. Новые версии выбирают ABI в порядке предпочтения
Android; если определить ABI не удалось или файл отсутствует (HTTP 404/410),
скачивают общий APK.

У всех APK и AAB одного релиза одинаковые ключ подписи и `versionCode`.
При новом релизе увеличивайте и версию, и номер сборки в `pubspec.yaml`
(например, `2.0.2+3` после `2.0.1+2`). Прибавка Flutter к `versionCode` за ABI
отключена, чтобы можно было обновляться между общим и отдельными APK.
